# 第五层检查结果与演示说明

更新：2026-11-18。入口：[第五层实验页](http://127.0.0.1:8765/showcase#layer/5)。

## 为什么原来看起来没有反应

原来的 `TwinModel.update()` 已由 MQTT 接收路径调用，每条新观测都会计算标称轮速、单步位置预测和校正量。不是空文件，但实现和展示确实不充分：

- 健康仿真与标称模型使用相同方程，轮速残差本来就为零。单步位置差只有亚毫米量级，原来按米保留四位小数，容易看成不动。
- 页面只有数字和单条残差曲线，没有实测与健康参考轨迹，也没有本层的实验入口或更新计数。
- 前端曾把 `residual_mps` 当作左右轮数组，后端实际返回最大绝对残差这个标量；前端靠临时重新计算兜底。
- 原来的校正状态每帧都直接同步观测，不能把它当作一辆持续独立行驶的小车。单步先验有意义，但需要与持续参考回放分别说明。
- 暂停时仍按网页轮询重复画点；旧状态也可能被显示为“健康”。缺口后曾把上条指令外推整个失联区间，无法代表期间实际发生的控制变化。
- 讲解把取消故障注入称为真实电机校准、把候选 PID 称为最优参数，超出了实际功能。

## 现在第五层实际完成的工作

| 输入 / 输出 | 含义与用途 |
| --- | --- |
| 输入 | L4 校验后的指令、轮速、位姿、样本编号、源时间与缺口标记。模型不读取源端故障设置。 |
| 标称轮速 | 左右轮分别按 `0.35 × u` 生成健康参考。 |
| 有符号轮速残差 | `实测 − 标称`，分别输出 `residual_left_mps` 和 `residual_right_mps`。负值表示比参考慢。`residual_mps` 保留为最大绝对值以兼容原接口。 |
| 单步先验 | 用上一个样本的控制量和上次校正位姿，按差速圆弧预测当前位姿。不能用当前指令解释已经发生的运动。 |
| 创新度 | 位置预测与新观测的距离，页面以 mm 显示；同时输出航向校正量。随后当前孪生状态同步到观测。这里是直接校正，不是卡尔曼滤波。 |
| 持续健康参考 | 从首次观测开始，仅回放收到的控制量，不逐帧用位置观测校正。和实测轨迹的偏移用来展示持续模型失配；它没有独立运行另一个循迹 PID。 |
| 一秒条件预测 | 从当前校正位姿出发，假设当前左右控制量保持一秒不变，输出 11 个预测点。下一步实际 PID 会更新指令，因此它不是已保证的未来路径。 |
| 数据缺口 | 无法知道缺失指令，恢复时重新对齐参考，`prediction_valid=false`。创新度此时无效，界面显示 `--`；CSV 必须结合该标记分析，不能把零值当作精确预测。 |
| 心跳 / 暂停 | 同一样本不重复推进模型，不增加更新计数，也不刷新模型计算时间。遥测过期保留最后观测，暂停当前判断与未来预测展示。 |
| 下游应用 | L6 使用 L5 的健康期望和残差，结合连续窗口判断驱动异常；历史曲线、CSV 与分析 JSON 保留预测和残差证据。 |

## 推荐录制顺序：约三分钟

1. 打开第五层，点“① Healthy baseline”。它从起点新建实验，使用默认 PID、理想灰度、固定种子。先看到“等待源端执行回执”，再看到“Applied at source”和新实验编号。
2. 指向“模型实际更新”计数和蓝色轨迹：数字持续增长，参考与实测重合，左右轮残差近零。这证明模型正常运转，零残差不是没有工作。
3. 点“② Left wheel −20%”。它以相同设置重新起跑，只改变源端左轮响应。健康模型参数仍是 0.35，不读注入设置。左轮残差为负，右轮约零，橙色参考和蓝色实测逐渐分离。刚起步 `uL=0.35` 时，标称为 0.1225 m/s，衰减后实测为 0.0980 m/s，残差为 −0.0245 m/s。转弯时随控制量变化，不会恒定在该数值。
4. 点顶部“暂停”。更新计数、源时间与图形停止推进，运输心跳仍可继续。按“单步”再增加一个采样，查看新的预测和校正。
5. 重新运行健康实验，点“Pause telemetry upload”。源端继续运动，模型时间和更新次数冻结；超过 1.2 秒显示过期。点“Resume telemetry upload”，缺口处重新对齐，再收到连续样本后恢复创新度评价。若轮询已经越过恢复的第一帧，可在导出 CSV 的 `prediction_valid` 列检查重同步记录。
6. 再做衰减实验，等连续窗口充分后点“③ View L6 evidence”。核对 `drive_left_low`、左侧约80%响应比例、右侧约100%。诊断需要至少20个连续样本、窗口跨度不少于0.38仿真秒、源时间达到0.6秒，其中驱动有效样本至少15个。
7. 回第五层导出 CSV 或孪生报告。JSON 包括当前 `twin`、一秒条件预测和 L6 诊断；CSV 是完整接收样本，网页轨迹为显示抽样，缺口不连线。

## 可直接使用的英文口播（操作说明保持中文）

> Layer five provides a healthy model that we can compare with the received observations. It does not read the source fault settings. Its nominal wheel speed is always zero point three five multiplied by the corresponding motor command.
>
> First, I will start the healthy baseline. The update count increases while the measured trajectory and healthy reference overlap. Both wheel-speed residuals are close to zero. Zero residual is the correct result when the simulated asset agrees with the nominal model; it does not mean that the model is inactive.
>
> Next, I will start the left-wheel reduction experiment. This creates a new run from the same initial state, with the same PID settings, ideal sensor environment and seed. Only the simulated left-wheel response is reduced by twenty percent. The left measured speed is now below its nominal value, producing a negative residual. The right-wheel residual remains close to zero.
>
> There are two different position comparisons. The one-step prediction uses the previous commands and is corrected by each new pose observation. Its position innovation is shown in millimetres. The orange healthy replay starts from the initial observation and continues without position correction between consecutive samples. Its growing separation from the blue measured trajectory demonstrates persistent model mismatch.
>
> The purple dashed curve is a conditional forecast: it assumes that the current commands remain constant for one second. The actual PID will update those commands, so this is not a guaranteed future route.
>
> When upload is interrupted, the twin retains its last observation. After recovery, missing commands cannot be reconstructed, so the reference is realigned and the missing interval is not treated as a valid prediction error. Layer six then uses the healthy reference and residuals as evidence for its diagnostic window.

## 源码入口

- `layers/l5_twin_model/twin_model.py`：单步预测、参考回放、预测有效标记、残差和条件预测。
- `runtime.py`：只在 L4 接受消息后调用模型，聚合模型状态与历史。
- `layers/l7_application/static/showcase.js`：第五层操作台、轨迹与双轮残差图、命令回执展示。
- `layers/l6_service_feedback/diagnostics.py`：持续窗口规则与下游服务。
- `layers/l4_data_management/storage.py`：完整接收 CSV；源端 CSV 仍保持独立格式。
- `test_components.py`、`test_system.py`：圆弧参考、健康 / 故障对照、无标签检测、心跳、缺口、真实 MQTT 和 MATLAB 轨迹回归。
