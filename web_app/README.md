## 在当前电脑打开

双击本目录的 **启动网页.cmd**。程序启动 broker 和 Python 网页服务，准备好后自动打开浏览器。

默认网页地址为 http://127.0.0.1:8765，MQTT 地址为 127.0.0.1:18884。保留启动窗口，按 Ctrl+C 可以停止应用和它启动的 broker。

也可以在 PowerShell 中执行。

```powershell
cd '<repository>\web_app'
& '.venv\Scripts\python.exe' -B app.py --open-browser
```

端口被占用时，关闭上一次启动的窗口，或显式指定其他端口。

```powershell
& '.venv\Scripts\python.exe' -B app.py --port 8766 --broker-port 18886 --open-browser
```

## 用一个连贯实验展示系统关系

1. 保持数据上传和命令回传开启。选择理想环境与“弱 P”，点击运行。小车端按 20 ms 固定步长推进。界面的仿真时间可以快于真实经过时间，右侧可选择 1×、4×、8×。
2. 切到“数据与孪生关系”。确认源端时钟、发送与接收计数、模型更新计数均有变化。每条观测携带特定资产会话、run_id、seq、源仿真时间和发送 UTC 时间。
3. 暂停“数据上传”。源端继续生成数据，数字端保留最后观测。超过 1.2 秒接收端经过时间后，数据状态标为过期。模型更新计数随观测停住。
4. 恢复上传。接收端看到序号缺口，用新观测重新同步状态。车辆状态与数据新鲜程度分别显示。
5. 观察弱 P 产生的误差或丢线停车。分析服务会提供默认 PID 对照建议。点击“按建议运行默认 PID 对照”，命令经 MQTT 到达源端，收到执行回执后启动新一组实验。环境、种子沿用该次观测对应的设置。新 run_id 与新参数会随下一批遥测返回。
6. 可另做命令中断实验。保持上传，关闭“命令回传”，再点击复位。监测仍更新，命令等待回执超时，源端没有执行该条复位。恢复回传后需要重新发一条新命令。

参数建议用于从相同初态比较两组实验。源端的 50 Hz PID 自身始终闭环工作。遥测采用每个仿真采样一帧，曲线为减轻浏览器开销抽样显示；CSV 导出保留实际接收的完整样本。

## 数据如何更新孪生

```text
仿真资产 car01
  传感器观测、轮速、位姿、已执行参数
             ↓ MQTT telemetry
接收端
  验证消息、去重、检查时间与序号
             ↓
  使用上次同步状态和标称轮速预测当前位置
             ↓
  用新位姿观测校正孪生状态，计算校正量
             ↓
  计算标称轮速残差、窗口误差、振荡与饱和
             ↓
  界面提示与默认 PID 对照建议
             ↓ 人选择建议
  MQTT command → 源端执行 → MQTT ack
             ↓
  新实验的观测重新更新数字端
```

三个主题共享前缀 `dt/car01/本次应用会话`，后缀分别为 `telemetry`、`command`、`ack`。每个应用实例使用独立的发布客户端与接收客户端，broker 是另一个进程。QoS 为 1，遥测与命令均不保留。源端对命令 ID 去重，界面用源端执行回执判断操作结果。超时表示执行结果未知，应对照源端状态与记录。

接收端计算 `expected_left_mps = 0.35 × uL`、`expected_right_mps = 0.35 × uR`。教师打开左电机 −20% 扰动后，实际轮速会偏离该标称模型，接收端将显示残差。预测位姿使用上条观测中的标称速度；新观测到达后，数字端校正状态。传输中断时无法获取新观测，暂停参数建议执行。

## 诊断结论怎样对应证据

网页的“诊断依据与下一步”把结论、数值证据、规则、建议及适用范围放在一起。分析只使用接收端最近 1 秒的数据；至少 20 个样本、跨度不少于 0.38 秒，并在源仿真时间达到 0.6 秒后开始持续异常判断。窗口中出现已知缺失区段时，先积累连续新数据。

| 判断 | 可检查的证据 | 建议及结论边界 |
| --- | --- | --- |
| 某侧驱动响应偏弱或偏强 | 对命令≥0.1 的样本，以 `0.35 × 命令` 生成健康轮速参考；至少15个有效驱动样本，最小二乘响应比例超出85%–115%，且有符号平均轮速残差的绝对值>0.005 m/s。 | 能定位到哪一侧命令—轮速关系异常。接着检查电源、驱动、轮速观测或电机系数；单靠这些信号无法确定具体机械、电气根因。 |
| 灰度观测与仿真参考不一致 | 8路灰度与同位姿理想参考的 RMSE>0.10，或二值判定差异比例>5%。 | 优先检查光照、遮挡、安装高度和参考地图。理想灰度是仿真对照信息，实车部署需要取得可用的独立参考。 |
| 控制振荡、饱和或高误差 | 过零≥3次/s且RMS>0.08；命令饱和>15%；有效检测时MAE>0.18。 | 支持参数对照实验。先排查感知和驱动偏差，再比较 PID；控制表现本身不足以确定根因。 |
| 丢线停车 | 源端停车码、当前有效传感器数量、接收端连续无黑线的观测时长。 | 这是保护动作。结合灰度参考与驱动残差，决定检查观测条件还是调整 PID。 |
| 遥测过期 | 接收端超过1.2秒没有有效新消息。 | 暂停当前诊断和参数建议，恢复上传后再判断。车辆的新状态此时未知。 |

驱动响应比例由观测和健康轮速计算，诊断逻辑不读取源端故障开关或注入系数。健康参考保持独立，响应比例和状态评价随新观测持续更新。单个速度尖峰需要与持续异常区别，样本不足时显示“诊断窗口尚不充分”。

健康参考、残差检测与故障类型区分的设计依据可参阅 [MathWorks 残差故障检测示例](https://www.mathworks.com/help/predmaint/ug/Fault-Detection-Using-Data-Based-Models.html)。本工程的阈值是明确列出的教学设定，实车使用需要另行标定和验证。

当出现持续驱动偏差或灰度参考差异时，系统优先给出检查建议；默认 PID 对照按钮用于观测新鲜、窗口充分、且主要表现为控制问题的情况。点击按钮后经 MQTT 启动新实验，需要看到源端回执。可点击“导出本次分析 JSON”保存当前证据、规则和建议。

录视频时可依次做五个小实验。

1. 理想环境与默认 PID，展示健康轮速参考和正常窗口。
2. 勾选“左侧电机响应降低20%”，展示左侧约80%的响应比例及负残差，右侧仍约100%。
3. 取消电机扰动，切换较强灰度扰动，展示感知参考偏差与驱动偏差的不同证据。
4. 选择理想环境与弱 P，观察保护停车及 PID 对照建议，然后执行建议并比较新实验。
5. 运行时暂停上传，展示“数据过期”，恢复后重新取得连续观测。

## 模型与实验边界

- 赛道来自 `../full_project/data/track_data.mat`，尺寸约 2.56 × 1.72 m。地图比例、轮距、电机系数和扰动幅度均沿用当前工程假设。
- 差速运动采用单周期解析增量，轮距 0.12 m，传感器前置 0.05 m、间距 0.008 m，8 路传感器按地图双线性插值采样。
- PID 使用有界条件积分与滤波微分。持续丢线 0.20 仿真秒后锁定停车。
- 随机环境包括光照增益、阴影偏置、传感器位置抖动和独立读数噪声。种子相同、输入相同，Python 版本内的实验可重复。Python 与 MATLAB 的随机数发生器不同，跨语言相同种子的噪声轨迹不保证一致。
- 当前用仿真资产代表数据源。未来接入实车需要实现对应采集适配器，并标定位姿、传感器与电机参数。网页里的状态评价采用可解释教学规则。
- 首个数字端位姿来自首次观测。随后每次新样本先预测再校正。源端时钟单独显示，目的是让断线实验能直观看到两端分离。

## 换电脑或重建环境

保留 `web_app` 与 `full_project` 的相邻目录关系。使用 Python 3.12 或 3.13，在本目录安装依赖。本机现有 `.venv` 已准备完成，复用了已安装的 NumPy、SciPy 等数值库。其他电脑应重建环境。

```powershell
python -m venv .venv
& '.venv\Scripts\python.exe' -m pip install -r requirements.txt
& '.venv\Scripts\python.exe' -B app.py --open-browser
```

MQTT 协议实现采用 [aMQTT broker](https://amqtt.readthedocs.io/en/latest/references/broker/) 与 [Eclipse Paho 客户端](https://eclipse.dev/paho/files/paho.mqtt.python/html/client.html)。
