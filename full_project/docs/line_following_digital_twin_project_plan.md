# 面向中小学生 PID 教学的循迹小车数字孪生仿真器

## 1. 项目定位

本项目建立一个基于 MATLAB/Simulink 的二维循迹小车数字孪生教学仿真器。学生不需要连接真实小车，只通过输入框或滑动条修改 `Kp`、`Ki`、`Kd`，观察虚拟小车、8 路灰度传感器、循迹误差和左右电机输出的变化。

具体的模块搭建、地图处理、信号命名、测试步骤和降级路线见：[技术路线与实施指引](line_following_digital_twin_technical_route.md)。

英文实验路线计划报告见：[Experiment Roadmap Report](line_following_digital_twin_experiment_roadmap_report.md)。

项目的核心不是三维外观，而是一个可解释的闭环：

```text
二维赛道地图
    ↓
8路虚拟灰度传感器
    ↓
线位置与循迹误差
    ↓
PD/PID控制器
    ↓
左右电机命令
    ↓
差速小车二维运动
    ↓
更新位置并再次读取赛道
```

长方体车身和圆柱体车轮只作为最后的显示层。三维模型直接跟随二维模型输出的 `x、y、theta`，不参与动力学计算。

## 2. 与老师电机示例的对应关系

老师的示例把电机及负载作为软件仿真的物理实体，并建立了“观测值—模型预期值—残差—状态评价—操作建议”的循环。本项目保留这个架构，但把评价对象改成循迹控制质量。

| 老师示例 | 本项目对应内容 | 第一版是否实现 |
|---|---|---|
| PE：电机和机械负载仿真 | PE：已选定硬件方案对应的虚拟小车、四个电机的左右分组、8路传感器 | 实现 |
| VE：电机正常行为模型 | VE：地图、灰度传感器模型、差速运动学、电机简化响应 | 实现 |
| DD：测量、预测、历史、单位 | 传感器值、误差、PWM、轮速、位姿、指标、运行记录 | 实现 |
| Ss：健康评价和建议 | 稳定性、响应速度、振荡、输出饱和、脱线提示 | 实现 |
| CN：数据和反馈连接 | 控制器输出到运动模型，运动状态返回传感器；保留未来连接 ESP32 的接口概念 | 以模型信号实现 |
| 断开遥测实验 | 暂停传感器更新或模拟数据失效，显示状态过期 | 可选增强 |
| 反馈命令实验 | 学生修改 PID 参数后，下一次仿真运行使用新参数 | 实现 |
| 模型不匹配实验 | 将电机响应、传感器噪声或摩擦参数改变，比较模型与结果 | 可选增强 |

项目应明确说明：由于课程要求不使用真实小车，本作品是“面向实体扩展的数字孪生仿真原型”。它具备 PE、VE、DD、Ss 和闭环 CN 的结构，但还没有真实 ESP32 的实时遥测。

## 3. 固定范围与非目标

### 3.1 固定范围

- MATLAB/Simulink 建立二维差速小车运动模型。
- 四个 TT 电机合并为左侧和右侧两组控制量。
- 根据赛道照片建立二维黑白地图。
- 建立 8 个虚拟灰度传感器。
- 实现 P、PD 和 PID 的可切换教学实验，学生主要调节 `Kp`、`Ki`、`Kd`。
- 显示传感器输出、线位置、误差、P/I/D 分量、左右电机输出、轮速、位姿和轨迹。
- 提供稳定、偏慢、振荡、饱和、脱线等量化状态提示。
- 先完成二维版本，再决定是否增加简化三维外观。

### 3.2 明确不做

- 不建立 SolidWorks 或 CAD 机械模型。
- 不做轮胎接触力、复杂摩擦、悬挂或碰撞动力学。
- 不做真实 TT 电机的电磁方程和电池化学模型。
- 不做真实 ESP32 通信、硬件在环或实时控制保证。
- 不开发 Scratch/Blockly 或自制代码编辑器。
- 不把照片直接重建为三维物体。
- 不承诺剩余寿命、故障概率或真实电机性能预测。

## 4. 系统边界与参数表

### 4.1 地图与几何参数

| 参数 | 符号 | 建议初始值 | 作用 |
|---|---:|---:|---|
| 地图实际宽度 | `map_width_m` | 按实物测量 | 像素到米的比例 |
| 地图实际高度 | `map_height_m` | 按实物测量 | 像素到米的比例 |
| 赛道黑线宽度 | `line_width_m` | 按照片测量 | 传感器黑线判断 |
| 小车轴距 | `L` | 由成品底盘尺寸确定 | 差速转向 |
| 传感器前置距离 | `sensor_front_m` | 实物估计 | 传感器相对车体位置 |
| 传感器间距 | `sensor_spacing_m` | 由8路板尺寸确定 | 8路采样点位置 |
| 地图像素比例 | `meters_per_pixel` | 自动计算 | 图像坐标转换 |

地图照片先处理为 `track_mask.png` 或 `track_data.mat`：黑线为1，背景为0。照片只作为二维赛道输入，不作为三维模型输入。必须记录实际地图长宽，否则轨迹速度和传感器间距没有物理尺度。

### 4.2 仿真时间和控制参数

| 参数 | 符号 | 作用 |
|---|---:|---|
| 固定步长 | `Ts` | 建议先用 0.02 s |
| 基础速度 | `u0` | 固定在教师配置中，避免学生同时调速度 |
| 比例增益 | `Kp` | 学生主要观察转向反应速度 |
| 积分增益 | `Ki` | 观察长期偏差和积分累积 |
| 微分增益 | `Kd` | 观察对摆动和过冲的抑制 |
| 电机输出上限 | `u_max` | 归一化为1或PWM上限255 |
| 积分限幅 | `I_max` | 防止积分饱和导致仿真失控 |
| 微分滤波系数 | `N` | 减少传感器跳变造成的尖峰 |

错误应归一化到 `[-1, 1]`。这样 `Kp/Ki/Kd` 的数值不会随着地图分辨率改变。初始增益只作为待标定起点，不能直接声称是最佳参数。

### 4.3 数据字典（DD）

每个仿真步记录一行数据，建议至少包含：

```text
t, time_s
x_m, y_m, theta_rad
sensor_1 ... sensor_8
line_position, line_error
P_term, I_term, D_term
correction
left_command, right_command
left_speed, right_speed
left_saturated, right_saturated
mean_abs_error_window
zero_crossing_rate
off_track
status_code
```

数据应保留单位、采样时间、模型版本和 PID 参数。仿真结束后导出 CSV，便于比较不同参数组。

## 5. 数学模型

### 5.1 控制器

采用误差反馈：

```text
e(k) = line_position(k) - vehicle_center
P(k) = Kp * e(k)
I(k) = I(k-1) + Ki * e(k) * Ts
D(k) = Kd * (e(k)-e(k-1)) / Ts
c(k) = P(k) + I(k) + D(k)
```

然后计算左右轮命令：

```text
left_command  = saturate(u0 - c)
right_command = saturate(u0 + c)
```

方向符号必须用一个简单场景校验：小车位于黑线左侧时，控制器必须产生使小车向右修正的输出。

第一版建议默认 `Ki=0`，先让学生比较 P 和 PD。启用 I 项时必须有积分限幅或反积分饱和。

### 5.2 电机和差速运动

四个电机按左右侧合并：

```text
left_front + left_rear  → left_command
right_front + right_rear → right_command
```

最小模型可以使用：

```text
vL = km * left_command
vR = km * right_command
v  = (vL + vR) / 2
omega = (vR - vL) / L
```

```text
dx/dt = v * cos(theta)
dy/dt = v * sin(theta)
dtheta/dt = omega
```

增强版再增加一阶电机响应：

```text
tau * dvL/dt + vL = km * left_command
tau * dvR/dt + vR = km * right_command
```

### 5.3 虚拟灰度传感器

8个传感器固定在车体前方。每个传感器的局部坐标经 `x、y、theta` 变换到地图坐标，再读取二值赛道图。

如果采样点落在黑线范围内，则输出1，否则输出0。也可以在增强版加入阈值、噪声和采样延迟。

传感器权重建议为：

```text
[-3.5, -2.5, -1.5, -0.5, 0.5, 1.5, 2.5, 3.5]
```

线位置用加权平均计算：

```text
line_position = sum(sensor_i * weight_i) / sum(sensor_i)
```

所有传感器均未检测到黑线时，第一版停止小车并标记脱线；不增加自动搜线状态机。

## 6. 交互界面和量化反馈

### 6.1 学生输入

输入形式采用数值输入框或滑动条，不限定为旋钮。每个参数应显示当前值、允许范围和简短说明：

- `Kp`：比例增益，控制偏差出现时的即时修正。
- `Ki`：积分增益，处理持续偏差，但过大会累积。
- `Kd`：微分增益，抑制变化过快和摆动，但过大会放大噪声。

建议用 Simulink Dashboard 的 Edit 或 Slider 连接到 Gain 参数。Dashboard 的 Edit 块可以在仿真期间输入参数，且可与其他 Dashboard 显示块组成交互面板；参数也可以和仿真信号一起记录。具体范围在模型完成标定后确定。

### 6.2 必须显示的量

界面至少分为四个区域：

1. **地图区**：赛道、小车矩形、传感器位置、实际轨迹。
2. **输入区**：`Kp`、`Ki`、`Kd` 数值输入或滑动条，以及复位按钮。
3. **瞬时量区**：8路传感器、线位置、线误差、P/I/D项、左右电机命令、左右轮速。
4. **评价区**：平均绝对误差、最大误差、振荡次数、饱和比例、脱线次数、完成时间和教学提示。

### 6.3 “预期值”和残差

借鉴老师示例，界面应同时给出实际输出和模型预期：

| 对象 | 实际/测量值 | 模型预期值 | 残差 |
|---|---:|---:|---:|
| 左轮速度 | `left_speed` | `km*left_command` 或一阶模型输出 | `left_speed - expected_left_speed` |
| 右轮速度 | `right_speed` | `km*right_command` 或一阶模型输出 | `right_speed - expected_right_speed` |
| 循迹误差 | `line_error` | 0 | `line_error` |
| 电机命令 | `left/right_command` | 0 到上限 | 是否饱和 |

这样可以区分两类问题：小车轨迹不稳定，或者电机模型没有跟随命令。没有编码器的真实小车时，“实际轮速”是仿真状态量，报告中必须称为“仿真轮速”，不能说成真实测量。

### 6.4 教学提示规则

提示使用“可能”而不是绝对诊断，并显示触发指标：

| 状态 | 建议判据 | 提示 |
|---|---|---|
| 稳定 | 平均绝对误差较小、零交叉率低、饱和比例低 | “循迹稳定；可以尝试提高基础速度或比较PD与PID。” |
| 响应偏慢 | 平均误差持续较大、输出未饱和、零交叉率低 | “响应偏慢，Kp可能偏小；适当增大Kp并观察。” |
| 振荡明显 | 误差在窗口内频繁改变符号、轨迹左右摆动 | “振荡明显，Kp可能偏大或Kd偏小。” |
| 积分累积 | I项持续增长、输出达到上下限、误差已经变小 | “积分可能过强，请减小Ki或观察积分限幅。” |
| 微分抖动 | D项幅值明显大于P项、命令高频变化 | “Kd可能偏大或传感器跳变，需要滤波。” |
| 电机饱和 | `left/right_command` 达到上下限的时间比例过高 | “控制输出已饱和，继续增大增益未必能提高响应。” |
| 脱线 | 连续一段时间8路均为0，或位置超出地图边界 | “小车已脱线，请复位并调整参数。” |
| 数值异常 | NaN、Inf、误差超范围或仿真时间超限 | “模型输入或参数异常，请检查初始状态和PID范围。” |

阈值由基准实验确定。计划书中可以先用相对阈值，例如“与稳定基准相比平均误差增加50%”，避免把未经测试的绝对数值写成结论。

## 7. 实验设计

每个实验只改变一个主要因素，并记录同一组指标。

### 实验A：P控制基础

- 固定 `Ki=0、Kd=0`。
- 使用低、中、高三个 `Kp`。
- 比较初始偏差修正时间、平均误差、最大误差和是否振荡。

### 实验B：加入D项

- 选取一个会摆动的 `Kp`。
- 逐步增加 `Kd`。
- 比较误差零交叉次数、峰值误差、轨迹平滑度和电机输出变化。

### 实验C：I项和积分饱和

- 固定一组PD参数。
- 使用 `Ki=0`、小Ki、大Ki。
- 显示I项、输出饱和时间和脱线结果。
- 解释为什么循迹系统不一定需要较大的积分作用。

### 实验D：模型和输入异常

- 传感器全部失效一段时间。
- 增加传感器噪声或延迟。
- 增大电机时间常数或左右侧响应不一致。
- 观察模型预期值、轮速残差、控制状态和脱线提示。

### 实验E：复位和可重复性

- 使用同一初始位置和同一组PID参数运行两次。
- 验证轨迹和指标一致。
- 修改参数后点击复位，确认积分、上一时刻误差、轨迹和统计值全部清零。

## 8. 验收标准

### 核心验收

- 二值赛道图可以正确载入并显示。
- 小车能够在开环输入下直行、左转、右转。
- 8路传感器位置随小车姿态变化。
- 传感器信号能计算出正确的循迹误差方向。
- 默认参数下小车能完成一圈或通过预先选定的有效赛段。
- 输入三个PID参数后，仿真可以重复运行。
- 界面显示轨迹、8路传感器、误差、P/I/D项、左右电机输出。
- 至少能识别稳定、响应偏慢、振荡和脱线四种状态。
- 可导出一组包含参数和指标的CSV记录。

### 增强验收

- 显示电机命令与仿真轮速的预期值、残差和饱和比例。
- 支持传感器噪声、电机不一致或模型不匹配实验。
- 支持暂停、单步运行和复位。
- 增加简化三维车身和车轮，并验证其位姿始终来自二维 `x、y、theta`。

## 9. 八周实施计划（每周2–3小时）

### 第1周：冻结需求与准备地图

产出：项目文件夹、参数表、赛道照片、二值地图初稿。

- 测量赛道实际长宽、线宽和小车基本尺寸。
- 裁剪并透视校正照片。
- 生成 `track_mask.png` 或 `track_data.mat`。
- 在 MATLAB 中显示地图坐标、起点和初始姿态。

### 第2周：完成二维差速运动

产出：开环车辆模型。

- 建立 `x、y、theta` 三个积分器。
- 输入左右命令，验证直行、左转、右转和原地旋转。
- 固定步长设置为 `Ts=0.02 s`。
- 确定左、右方向符号。

### 第3周：完成8路灰度传感器

产出：可视化传感器阵列。

- 写出局部坐标到地图坐标的变换。
- 读取二值地图中的8个像素位置。
- 显示8路0/1输出和传感器点。
- 测试直线、弯道和脱线。

### 第4周：完成误差和P/PD闭环

产出：小车可以自动循迹。

- 计算加权线位置和归一化误差。
- 建立P和PD控制器。
- 添加左右命令饱和。
- 调整一组能通过有效赛段的基础参数。

### 第5周：完成PID、模型输出和安全逻辑

产出：可重复运行的完整二维模型。

- 加入I项和积分限幅。
- 加入D项离散计算和简单滤波。
- 输出P/I/D、命令、轮速和残差。
- 加入脱线、越界、NaN和仿真超时处理。

### 第6周：完成学生交互界面

产出：学生可以只修改三个PID参数。

- 使用数值输入框或Dashboard Edit/Slider。
- 设置参数上下限和默认值。
- 显示轨迹、传感器、误差和左右电机量。
- 增加复位、运行/暂停和数据记录。

### 第7周：完成评价与测试

产出：四组可演示实验和CSV结果。

- 实现平均误差、峰值误差、零交叉率、饱和比例和脱线次数。
- 实现稳定、偏慢、振荡、脱线提示。
- 完成P、PD、PID和异常输入实验。
- 检查同一参数重复运行是否一致。

### 第8周：整理报告和可选三维

产出：最终模型、报告、演示视频或截图。

- 优先修复二维模型、坐标和提示规则问题。
- 整理PE、VE、DD、Ss、CN结构图。
- 导出三组典型结果：参数偏小、参数偏大、参数合适。
- 只有二维版本稳定后，才增加长方体车身和圆柱体车轮。

## 10. 时间预算与取舍

核心版本约需16–20小时：

```text
地图与坐标：2–3小时
二维运动学：2–3小时
8路传感器：3–4小时
P/PD/PID控制：3–4小时
界面与数据记录：3–4小时
测试与报告：3–4小时
```

三维外观、噪声、模型不匹配和更多提示属于4–8小时增强项。若第5周结束时二维闭环还不稳定，应取消三维和异常实验，把时间用于坐标、采样时间、饱和和复位问题。

## 11. 主要风险和处理办法

| 风险 | 现象 | 处理办法 |
|---|---|---|
| 图片透视或坐标方向错误 | 传感器位置与赛道不重合 | 先显示传感器点，不接控制器，逐点校验 |
| 误差符号相反 | 小车越修正越偏 | 用左偏初始状态做方向测试 |
| 赛道过复杂 | 分叉或交叉处无法判断 | 第一版只截取无分叉闭合赛段 |
| PID量级不合适 | 小车瞬间旋转或几乎不动 | 先归一化误差和命令，再标定增益范围 |
| 积分风up | 输出长期卡在上限 | 积分限幅或启用反积分饱和 |
| D项尖峰 | 电机输出抖动 | 离散微分加滤波，记录D项单独曲线 |
| 仿真太慢 | 图形更新影响控制 | 控制模型固定步长，显示可以降低刷新频率 |
| 把仿真状态当真实测量 | 报告过度声称 | 使用“仿真轮速”“模型估计”，明确实体扩展限制 |

## 12. 最终报告结构

1. 问题背景与中小学生PID教学目标。
2. 课程作业要求和项目边界。
3. PE、VE、DD、Ss、CN概念映射。
4. 赛道照片到二维地图的处理方法。
5. 差速运动学、传感器和PID公式。
6. Simulink子系统和数据流。
7. 交互参数和状态评价指标。
8. P、PD、PID三组实验结果。
9. 参数异常、脱线和模型不匹配实验。
10. 仿真限制与未来接入ESP32的接口设想。
11. 八周工作量和完成情况。

最终演示应固定展示三种结果：`Kp/Kd`不足导致响应偏慢、增益过大导致振荡、经过调整后稳定循迹。每种结果同时给出轨迹、误差曲线、P/I/D输出、左右电机输出和提示信息。

## 13. 建议的 Simulink 模型层次

顶层模型建议只保留七个清晰的子系统。每个子系统都应有输入、输出和单位说明，避免把所有公式堆在一个画布上。

```text
LineFollowerTwin.slx
├── TrackMap
├── VirtualGraySensors
├── LinePositionAndError
├── PIDTeachingController
├── MotorResponse
├── DifferentialDriveKinematics
└── EvaluationAndLogging
```

### TrackMap

输入为二值地图、地图比例和地图原点，输出为地图显示信号和传感器查询接口。地图文件在仿真开始前加载一次，不要在每一个仿真步重新读取照片。

### VirtualGraySensors

输入为 `x、y、theta`，输出为：

```text
sensor[1:8]
sensor_count
all_white
all_black
sensor_world_x[1:8]
sensor_world_y[1:8]
```

`sensor_world_x/y` 用于动画和调试。先确认传感器点落在正确位置，再接入控制器。

### LinePositionAndError

输入为8路传感器，输出为：

```text
line_position
line_error_normalized
line_detected
off_track
```

当所有传感器均为0时，第一版直接产生 `off_track=1`，并把控制器切换到安全停止状态。不要在第一版加入“记住上次方向并自动找线”。

### PIDTeachingController

输入为归一化误差和 `Kp、Ki、Kd`，输出为：

```text
P_term, I_term, D_term
correction
left_command, right_command
left_saturated, right_saturated
```

内部应有 `Unit Delay` 或 `Memory` 保存上一时刻误差，避免微分支路形成不清晰的代数环。积分支路需要限幅，输出需要 `Saturation`。

如果安装的 MATLAB 版本提供 Discrete PID Controller block，可以使用其离散模式和内置抗积分饱和；如果需要教学透明度，则将 P、I、D 三个支路分别搭出来，并把每个支路输出接到 Scope 或 To Workspace。控制器使用离散采样时间时，必须在报告中写明 `Ts`、输出上下限和微分滤波设置。

### MotorResponse

第一版直接使用比例模型：

```text
left_speed = km * left_command
right_speed = km * right_command
```

第二版才增加一阶延迟。无论采用哪一版，都要同时输出：

```text
expected_left_speed
expected_right_speed
left_speed_residual
right_speed_residual
```

报告中将它们称为“模型轮速”和“仿真轮速”，避免把没有真实编码器的状态称为测量值。

### DifferentialDriveKinematics

输入左右轮速，输出 `x、y、theta、v、omega`。它只负责二维运动，不读取 PID 参数，也不直接读取传感器。这样可以单独测试车辆运动。

### EvaluationAndLogging

该子系统收集信号并计算窗口指标。建议使用固定长度的滑动窗口，例如最近 `W=1 s` 的数据。它不改变车辆状态，只产生服务输出和记录。

## 14. 初始化文件与可重复运行

建议建立一个 `init_line_follower.m`，每次打开模型前运行。示例结构如下，实际数值要在地图和模型完成后标定：

```matlab
% init_line_follower.m
cfg.Ts = 0.02;
cfg.map_width_m = 1.20;
cfg.map_height_m = 0.80;
cfg.line_width_m = 0.025;
cfg.wheel_base_m = 0.12;
cfg.sensor_front_m = 0.055;
cfg.sensor_spacing_m = 0.010;
cfg.base_speed = 0.35;
cfg.max_command = 1.0;
cfg.integral_limit = 0.30;
cfg.derivative_filter = 20;

% 教师默认参数；学生只修改这三个值
Kp = 0.80;
Ki = 0.00;
Kd = 0.08;

% 用于比较实验的固定初始状态
x0 = 0.10;
y0 = 0.20;
theta0 = 0.0;

% 轨迹和信号记录开关
enable_logging = true;
```

参数文件的作用是保证每次复位使用相同的地图、初始姿态、基础速度和采样时间。学生修改 `Kp、Ki、Kd` 后，模型应记录这三个值，否则导出的曲线无法追溯。

## 15. 指标的具体定义

界面上的每个评价值都要有明确算法，避免只显示一个没有解释的“综合分数”。

### 平均绝对误差

```text
MAE = mean(abs(line_error_normalized))
```

只在小车尚未脱线的有效样本中计算；如果脱线，另外记录脱线时间和脱线次数。

### 最大误差

```text
PeakError = max(abs(line_error_normalized))
```

用于显示转弯时最严重的偏离。

### 误差零交叉率

统计一个窗口内 `line_error` 正负号改变的次数，再除以窗口持续时间。零交叉率高表示左右反复修正，通常对应可见摆动。

### 电机饱和比例

```text
SaturationRatio = saturated_samples / total_samples
```

左右电机分别计算，也可以显示两者最大值。它可以解释为什么“继续增大Kp”没有带来更快的实际响应。

### 轨迹稳定性

第一版采用三个条件的组合，而不是单独依赖一个阈值：

```text
稳定 = MAE较小 AND 零交叉率较低 AND 饱和比例较低
```

具体阈值在第7周用默认参数、低Kp和高Kp三组基准实验确定。计划书不提前固定绝对数值，因为不同赛道尺度和基础速度会改变指标量级。

### 综合评分（可选）

如果课程演示需要一个分数，可以使用透明的加权形式：

```text
score = 100 * (
    0.45 * (1 - clamp(MAE / MAE_ref, 0, 1))
  + 0.25 * (1 - clamp(PeakError / Peak_ref, 0, 1))
  + 0.20 * (1 - SaturationRatio)
  + 0.10 * completion_flag
)
```

`MAE_ref` 和 `Peak_ref` 由教师基准运行确定。分数只用于学习反馈，不代表真实机器人性能，也不应取代误差曲线。

## 16. 对照老师示例的测试矩阵

老师示例的价值之一是测试“连接正常”和“模型正确”是两件不同的事。小车项目可以使用以下矩阵：

| 测试 | 操作 | 预期结果 | 对应概念 |
|---|---|---|---|
| 正常闭环 | 默认参数运行 | 轨迹、传感器和电机输出同步变化 | PE→DD→VE→Ss |
| 参数改变 | 暂停后改变Kp，单步运行 | 新样本使用新参数，旧记录不被改写 | 设置路径与运行路径分离 |
| 传感器失效 | 强制8路输出为0 | 车辆停止，状态为脱线，误差标记无效 | 数据质量与服务状态 |
| 地图边界 | 初始位置放在地图外 | 仿真停止并报告越界 | PE边界条件 |
| 电机不一致 | 令右轮 `km` 减少10% | 产生稳定偏差，轮速残差增加 | VE模型不匹配 |
| 传感器噪声 | 加入随机翻转或阈值噪声 | D项和命令抖动可能增加 | DD质量与鲁棒性 |
| 延迟 | 传感器延迟一个或多个采样步 | 反应变慢或振荡增加 | CN时延 |
| 复位 | 修改参数、运行后点击Reset | 轨迹、积分、历史、指标回到初始状态 | 可重复实验 |
| 重复运行 | 同一初始状态与参数运行两次 | 无随机噪声时结果一致 | 仿真可复现性 |
| 真实连接边界 | 把仿真接口字段列成未来ESP32协议 | 当前仍使用模型信号，不声称已接硬件 | 未来CN接口 |

其中“传感器失效”和“电机不一致”最适合在报告中展示，因为它们能说明系统不仅画出了轨迹，还能识别数据或模型的问题。

## 18. 给老师展示的最小闭环叙述

答辩时可以按下面的顺序讲：

1. **Purpose**：让学生通过循迹小车理解 PID 参数对误差和电机输出的影响。
2. **PE**：依据已选定 ESP32、4个TT电机和8路灰度板定义一个虚拟小车。
3. **Boundary**：只覆盖一辆小车、一张二维赛道和一次闭环循迹；不覆盖真实电路和机械接触。
4. **VE**：用传感器采样、差速运动学和简化电机响应表示实体行为。
5. **DD**：记录传感器、误差、P/I/D、命令、轮速、位姿、残差和评价指标。
6. **Ss**：提供稳定性评价和面向学生的参数调整提示。
7. **CN**：控制器输出更新虚拟小车，小车姿态又更新传感器输入；PID参数作为教学反馈输入。
8. **为什么不只是Dashboard**：Dashboard只提供输入和显示，实际的虚拟实体、传感器、运动模型和闭环控制在Simulink内部持续运行，并由每一步的状态产生下一步输入。

最后必须说明当前没有真实小车遥测，因此“数字孪生”在本项目中是面向实体扩展的仿真原型。未来只需保持 `sensor[1:8]、left_command、right_command、x、y、theta` 等字段接口一致，便可以把 ESP32 数据源替换到 PE/CN 位置。
