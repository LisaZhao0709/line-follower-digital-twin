# 循迹小车通信模块技术指南

2026-11-04 已新增可运行的 Python 网页实现，包含真实 MQTT broker、遥测接收、孪生状态更新、分析建议和命令执行回执。当前启动及验证步骤见[网页应用使用说明](../../web_app/README.md)。本文提供通信架构与实验设计。

**目标**　让观众在两端看到同一条小车数据，并能分别验证“监测端收到了什么”和“实验端实际执行了什么”。适用对象为当前 MATLAB/Simulink 完整八周工程。下文将已有实验、可以手工执行的通信演示、需要开发的功能分别说明。

## 1　对照课堂项目，缺口在哪里

| 课堂实验 | 小车工程里已经能做什么 | 还应展示什么 |
|---|---|---|
| 01　监测与反馈 | 8 路传感器驱动 PID，左右轮命令改变下一步位姿；界面有调参建议，下一次实验采用学生输入的参数。 | 单独切断数据上传后，接收端保留最后有效值；单独切断命令回传后，仍能看数据，但新参数未执行。课堂 01 自身采用同进程的两条逻辑通道。 |
| 02　采集、传输与质量 | 模型按 20 ms 采样，CSV 有仿真时间、传感器、误差、轮速和停车原因，可注入传感器中断。 | 将小车自己的数据经 broker（消息代理）发给独立订阅端，展示到达时间、序号缺口、重复消息和数据过期。课堂 02 已有针对 Motor01 的实现。 |

## 2　先认清两种中断

以下来自已有的[传感器中断实验原始记录](../results/experiments/run_20261102_195947_445/experiment_trace.csv)。`uL`、`uR` 是归一化左右电机命令。

| 仿真时间 | 8 路传感器 | 电机使能 | 左右命令 | 能得出的结论 |
|---|---|---:|---|---|
| 1.00 s | 全 0 | 1 | 约 0.348 / 0.352 | 从这一帧开始无黑线，数据依然有效。 |
| 1.20 s | 全 0 | 0 | 0 / 0 | 连续丢线达到 0.20 s，保护动作生效。 |
| 1.42 s | S4、S5 再次有效 | 0 | 0 / 0 | 传感器读数恢复，停车仍锁定。 |

通信中断的表现不同。源端可以继续生成或回放这些帧，接收端在断开期间只能显示“最后收到的帧，已过期”。接收端若自行把 8 路读数补成零，会凭空制造一次丢线。建议界面分开显示**车辆状态**（循迹、丢线停车）和**数据状态**（正常、过期、无有效数据）。

## 3　先把三帧真实实验记录发出去

这是一个独立的小实验。数据来自 Simulink 已完成的仿真，传输经过本机 MQTT broker。它可以验证上行链路，完整的双向功能见第 4 节。以下 PowerShell 命令以 Mosquitto 的 Windows 常见安装路径为例。若已安装在别处，替换三个终端中的程序路径。本次编写指南时，在本机 PATH 与常见安装目录均未发现这套命令行工具。需要时使用 [Eclipse Mosquitto Windows 安装包](https://mosquitto.org/download/)。

**终端 A · 启动 broker。** 课堂配置仅监听本机 127.0.0.1:1883。若该地址已有可用的 MQTT broker，可直接进入终端 B。

```powershell
& 'C:\Program Files\mosquitto\mosquitto.exe' -v -c 'F:\DIGITAL TWEEN\chapter-02-students\chapter-02\config\mosquitto.conf'
```

**终端 B · 先订阅。** 保持窗口打开，等待来自小车的消息。

```powershell
& 'C:\Program Files\mosquitto\mosquitto_sub.exe' -h 127.0.0.1 -p 1883 -t 'dt/car01/telemetry' -q 1 -v
```

**终端 C · 发送三帧。** 序号从 0 开始，第 50、60、71 帧分别对应上表三个时刻。每次执行产生新的回放编号，便于重复演示。

```powershell
$run = 'run_20261102_195947_445'
$file = "<repository>\full_project\results\experiments\$run\experiment_trace.csv"
$rows = @(Import-Csv -LiteralPath $file)
$stream = [guid]::NewGuid().ToString()
foreach ($seq in 50,60,71) {
    $row = $rows[$seq]
    $packet = [ordered]@{
        run_id      = $run
        stream_id   = $stream
        seq         = $seq
        t_sim_s     = [double]$row.time_s
        sent_utc    = [datetime]::UtcNow.ToString('o')
        sensors     = @(1..8 | ForEach-Object { [int]($row."S$_") })
        enabled     = [int]$row.enabled
        stop_reason = [int]$row.stop_reason
        uL          = [double]$row.uL
        uR          = [double]$row.uR
    }
    $packet | ConvertTo-Json -Compress | & 'C:\Program Files\mosquitto\mosquitto_pub.exe' -h 127.0.0.1 -p 1883 -t 'dt/car01/telemetry' -q 1 -s
    if ($LASTEXITCODE -ne 0) { throw "第 $seq 帧发布失败，请检查终端 A 和端口。" }
}
```

**通过条件**　终端 B 收到该回放的三个不同序号，且序号 60 对应 `t_sim_s=1.2`、`stop_reason=1`、`uL=uR=0`。截取订阅端的消息和 CSV 同一行作为一对证据。这里是人工抽取三帧，序号跳跃来自选帧。做丢包实验时应切换为第 4 节的连续逐帧发送。命令参数见 [Mosquitto 发布工具说明](https://mosquitto.org/man/mosquitto_pub-1.html) 和 [订阅工具说明](https://mosquitto.org/man/mosquitto_sub-1.html)。

## 4　把演示扩展成小车通信模块

### 4.1　分工和接口

```text
仿真实验端 ── telemetry（带序号的轨迹帧）──→ 本机 broker ──→ 监测端
监测端     ── command（请求新实验）────────→ 本机 broker ──→ 仿真实验端
仿真实验端 ── ack（命令执行结果）──────────→ 本机 broker ──→ 监测端
```

| 主题 | 发送方 → 接收方 | 应用层约定 |
|---|---|---|
| `dt/car01/telemetry` | 实验端 → 监测端 | 采用第 3 节的数据包。轨迹图再加 CSV 中的 `x_m`、`y_m`、`sensor_error`。源时间用仿真秒，发送时间用 UTC；接收端另记到达时间。 |
| `dt/car01/command` | 监测端 → 实验端 | 例如 `{"command_id":"demo-01","action":"run_pid","Kp":0.45,"Ki":0.015,"Kd":0.03}`。一次点击分配一个唯一 ID。 |
| `dt/car01/ack` | 实验端 → 监测端 | 原样带回 `command_id`。状态用 `accepted`、`completed`、`rejected` 或 `failed`。完成时附新 `run_id`、实际 PID、完圈标志和圈时；未完圈用 JSON 的 `null` 表示圈时。 |

**上行实现**　写一个回放发布器，读取某次实验的 `experiment_trace.csv`，从第 0 行顺序发送，按相邻 `time_s` 的差值安排 1 倍速回放。每个实验目录对应一个 `run_id`，每次开始回放另分配一个 `stream_id`。同一主题用有序单源发送。监测端从 MQTT 接收数据，为轨迹、传感器灯和状态文字提供值。将源端最新序号和接收端最新有效序号并排显示，掉线时可以直接比较。

**下行实现**　让实验端监听 `command`。收到 `run_pid` 后检查参数为有限标量，范围为 `Kp ∈ [0,20]`、`Ki ∈ [0,2]`、`Kd ∈ [0,0.5]`。接受请求后用独立工作线程或任务调用现有 MATLAB 函数，保持 MQTT 接收循环可用。忙时拒绝新请求并返回原因。同一 `command_id` 的重发返回已有状态，最多创建一次实验。三个主题均用 QoS 1，关闭消息保留，避免后加入的实验端执行旧命令。

```matlab
% 实验执行端调用的现有入口，三个数值来自通过校验的请求
[record, trace, cfg, directory] = run_twin_experiment(Kp, Ki, Kd);
```

在 MATLAB 输出落盘后，实验端才发送 `completed` 并开始发布新实验的轨迹。可从 `directory` 得到新编号，从 `cfg` 得到实际增益，从 `record` 得到结果。失败时回传 `failed` 和原因。建议从“弱 P”发起一次“改用默认 PID”的请求；学生看到的是一次新实验的效果，原始轨迹仍可用于对照。若只收到 MQTT 层的发布确认，界面显示“已发送，等待实验端回执”。回执超时显示“结果未知”，有无执行还要查实验端日志。

**可复用部分**　实验端使用 [MATLAB 实验入口](../run_twin_experiment.m)；接收端可参考课堂 [MQTT 连接与订阅代码](../../../chapter-02-students/chapter-02/dt_demo/mqtt_io.py)。课堂类里固定了 `dt/Motor01/#`，还会按内部会话 ID 过滤，复用时要为小车设置自己的主题和消息契约。课程自带的 `Simulation fallback` 可用于调试界面，录制 MQTT 实验时选用真正的本机 broker。

### 4.2　接收端怎样判断数据可靠

| 现象 | 判定和显示 |
|---|---|
| 首次订阅或新回放 | 收到第一条有效帧前显示“等待数据”。为当前回放单独保存最后有效序号、值和到达时间。 |
| 重复、迟到、跳号 | 按 `(stream_id, seq)` 去重。同一回放中，迟到帧只记日志；跳号时标出缺失区段，曲线留空。原始接收日志保留实际到达顺序。 |
| 内容不合法 | 检查 8 路数字量是否均为 0/1，`uL/uR` 是否为有限数且在 [0,1]，时间字段和序号是否有效。在单独的拒收日志记录原因；保留上一条有效值。 |
| 长时间没有有效新帧 | 1 倍速连续回放期间，可把 **0.5 秒接收端经过时间**设为演示阈值。用本机单调时钟计时，超时标“过期”，显示最后有效时间。计划结束时应标“回放完成”，避免把正常结束诊断成掉线。 |
| 收到全零传感器值 | 合法的全零向量仍可代表车辆正在丢线。车辆保护按**仿真时间**累计 0.20 秒，通信过期按**接收端时间**判断。 |

## 5　验收实验与录像证据

**随机灰度的接入**　小车新增的 `environment_level`、`environment_seed` 可以产生光照、阴影、颠簸及读数噪声。遥测应发送 `strength1..8` 对应的实际灰度和 `S1..8`，附上环境等级与种子。对照图可另传 `ideal_strength1..8`，供教学观察使用。噪声可能让传感器误判，但只要消息结构、范围、时序都有效，这条观测仍然可以通过通信质量检查。建议分别显示“传输是否有效”“传感器观测是否可靠”“车辆是否脱线”。地面和光学扰动的解释见[工程使用说明](../使用说明_完整八周.md)。

以下是**拟新增模块的验收标准**。先做 1–3 可覆盖上行传输、异常识别和数据质量；加入 4–5 可覆盖反馈指令。各实验分别记录源端发送、订阅端接收和实验执行结果。

| 实验 | 操作 | 判为通过的可观察结果 |
|---|---|---|
| 1　完整记录上传 | 对已有丢线实验连续发送全部帧，保留原始序号。 | 接收端与 CSV 逐帧对应。第 60 帧停车、第 71 帧恢复读线但仍停车；数据状态全程可为正常。 |
| 2　只切上行 | 在较长的默认实验回放中，让源端继续推进，暂停发布 2 秒，再恢复发送当时的新帧。 | 两端序号暂时分离；监测端在阈值后标过期并保留最后值；恢复后显示序号缺口。 |
| 3　内容质量 | 在连续流中重发一帧，再发送一帧含 7 个传感器值的异常消息。 | 重复帧只更新一次，异常帧有拒收原因；两者都不覆盖最近的有效新样本。 |
| 4　下行成功 | 先展示弱 P 实验，再从监测端请求默认 PID。 | 接收端看到同一命令 ID 的受理、完成回执；新目录的参数正确，新 `run_id` 数据开始到达。已有基准为弱 P 在 14.76 s 脱线停车、默认 PID 在约 87.50 s 完圈。 |
| 5　只切下行 | 保持遥测连接。在实验端取消命令订阅，等待取消订阅确认，再从监测端发一条新 ID 的命令。 | 上行序号继续增长。监测端等待回执超时；对照实验端日志及结果目录，确认该请求没有启动实验。恢复订阅后发送另一条新 ID，再验证能执行。 |

**视频里怎么讲**　通信部分留约 90 秒。先用 20 秒展示同一条停车记录在 CSV 和订阅端如何对应，再用 30 秒切断上行，强调“此时我们只知道数据变旧，无法判断车是否停车”。若已实现下行，用剩余时间展示一次经回执确认的 PID 改参和新圈时。屏幕标注“仿真轨迹回放，MQTT 本机传输”，老师就能分辨数据来源、传输方式和控制发生的时刻。
